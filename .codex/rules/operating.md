# Operating Rules

- Be concise and practical.
- Prefer the repository's current structure over introducing new frameworks.
- Keep durable rules short; put task-specific procedures in runbooks or skills.
- Separate raw evidence, interpretation, and user-facing conclusions.
- Do not silently choose between materially different destinations, deletions, hardware actions, git history changes, or persistent workflow changes.
- When the user says to proceed autonomously, make the smallest defensible assumption and state it briefly.
- Maintain this repository as a multi-user setup. Do not commit private keys, personal credentials, passwords, real tokens, or user-specific machine state.
- Prefer checked-in examples and setup instructions over checked-in local secrets.
